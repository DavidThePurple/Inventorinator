# Inventorinator v0.1.1-alpha.2 (unreleased)

## Role builder groundwork

Owners can open Remote Settings → Role builder to create named templates from
View only, Build operator, Inventory editor or Workshop manager presets.
Each permission has an operation description; destructive operations are
marked separately. Templates can be edited, duplicated and deleted.

On server v25, owners can assign saved custom roles to devices.
Existing built-in roles remain authoritative. Ownership, recovery, device
removal and template management are not delegable through a template.

## DigiKey and offline role drafts

Use Add → Search DigiKey to search with your own developer credentials,
select a packaging variant and review the item before saving. Owned quantity
starts at zero; supplier stock and quotes do not become owned quantity or cost.
DigiKey import is confirmed working by the user (September 19, 2026).

Remote Settings → Role builder (local) stores design drafts on this device without
contacting Supabase. Local drafts never grant access or upload automatically.

## Remote Sync upgrade

Back up your PostgreSQL database before applying **schema 33** on the server.
The planned bundle is `Inventorinator-v0.1.1-alpha.2-Supabase-schema33.tar.gz`,
containing the updater, connector and every migration through 033.
This release and its downloads have not been published yet.

From the extracted bundle, replace the server bundle as a complete unit and
run `./apply-migrations.sh`. Confirm `Inventorinator schema v33 is ready.`
before opening the new app. The migrations add draft-role storage, owner-only
supplier credentials, per-device Scratch Pad backup, optional workspace sharing,
and note links to workshop records. Removed-device notes are retained for the
Owner or Admin who removed that device. Existing memberships and inventory data
are unchanged. See [v33 server update instructions](../server-update-v33.md).

Previous release instructions remain in `v0.1.1-alpha.md`.


## Core workflow completion

Adds permission-enforced custom roles, durable sync conflict review, higher-resolution supplier photo previews with zoom, and local searchable reports with PDF preview/save/share/print. See [completion details](../completion-pass.md) and [server update](../server-update-v25.md).

## Import review and undo

File imports now allow row selection and correction before saving. Import history supports persistent undo of unchanged, unreferenced imported items. Shared undo requires schema 30 and protects newer remote edits. See [import review and undo](../import-review-and-undo.md).

## Scratch Pad device recovery

Re-added devices reclaim note backups using their stable identity. Administrators can restore older archived notes to a selected device. Requires schema 31; see [server update](../server-update-v31.md).

Workspace Owners can now edit or delete any backed-up Scratch Pad note, including unshared and archived notes. Author devices apply those changes on sync; stale backups cannot reverse them. Other roles retain their existing access.

## Automatic filament drying times

Filament uses material/weight timer estimates when no duration is saved; missing weight assumes 1 kg. Owners can optionally require manual durations. See [drying timers](../filament-drying.md).

## Modified sorting

Inventory can be sorted by modification date and time, newest first by default. Existing records use their added date until changed. Modification timestamps persist across restart and sync; schema 33 preserves the newer timestamp when offline edits arrive out of order.

## Windows label OCR

Label capture on Windows now reads text on the device with a bundled Tesseract engine, as on Linux, instead of stopping with "not available on this platform". The Windows package grows by about 12 MB uncompressed (the 7.5 MB engine plus 4 MB of English language data). No server change is required.

## Secure sign-in storage (experimental)

Remote Settings has a new **Secure sign-in storage** switch, off by default. Turning it on keeps this device's Remote Sync sign-in in the system keyring (Windows Credential Manager, Android Keystore, or the Linux Secret Service) instead of the database file. A warning explains that recovering the stored sign-in becomes the operating system's job: if the keyring is reset or lost, sign in to Remote Sync again on that device. Your inventory and the shared inventory are unaffected. Turning the switch off moves the sign-in back. Linux needs a running Secret Service such as GNOME Keyring or KDE Wallet. No server change is required.

## App lock (PIN)

An optional PIN screen for shared terminals, off by default. Set a PIN in Personalization settings and a lock button appears at the top right. Locking hides everything behind **Unlock with PIN**. You can also lock automatically after a set time of inactivity. Setting a PIN shows a one-time unlock key that opens the lock screen's **Forgot PIN?** path. This is a screen lock, not encryption. See [App lock](../app-lock.md).
