# Security policy

## How to report a security problem

1. **Preferred: a private GitHub advisory.**
   [Report a vulnerability](https://github.com/DavidThePurple/Inventorinator/security/advisories/new)
   or open the repository's **Security** tab and choose **Report a vulnerability**.
   Only you and the maintainer can see it.
2. **If that does not work for you,** message the maintainer on GitHub
   ([@DavidThePurple](https://github.com/DavidThePurple)) or X
   ([@davidthepurple](https://x.com/davidthepurple)). Say you have a security
   report and ask how to send it privately. Leave the details out of the message.
3. **If you cannot reach the maintainer either way,** open a public issue that
   says only that you have a security report. Include no details, and the
   maintainer will arrange a private channel.

This is a small project maintained by one person. Reports are read as soon as
possible, but there is no guaranteed response time.

## What not to post publicly

Please do not publish credentials, private inventory exports, captured labels,
or exploitable security details in a public issue, pull request or post.

## What to include

- The affected platform (Linux, Windows or Android) and the app version.
- The sync mode: local only, or Remote Sync.
- Whether a hosted or self-hosted Supabase instance is involved.
- Steps to reproduce, and what someone could do with the problem.
- Redacted examples only. Remove real tokens, keys, workspace IDs and server
  addresses.

## Supported versions

Supported security fixes target the latest source revision.
