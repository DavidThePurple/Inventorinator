# Kit and BOM package import (v1.1.0+)

Inventorinator v1.1.0 (the next release, currently unreleased) adds desktop
import for `.inventorinator-kit.json` packages. A package can be written by
hand, exported from another tool, generated by a script, or created with
optional help from an AI research tool. Inventorinator performs the validation,
preview, and confirmed import locally.

No AI account, API key, or usage fee is built into Inventorinator. The app does
not send the package to an AI service.

## Import a package

1. Download Inventorinator v1.1.0 or newer for Linux or Windows.
2. Create or obtain a package using the documented format below.
3. Save it as `something.inventorinator-kit.json`.
4. Open **Catalog** and choose **Import kit**.
5. Review the validation and import preview.
6. Confirm the import.

Inventorinator imports the catalog products, BOM sections and quantities,
sources, associated machines, and the kit. Each newly created inventory item
starts at quantity `0`; importing a BOM never claims that a part is owned.
Existing products are reused by stable package ID or normalized name and type.
Importing the same package again updates the kit instead of duplicating it.
Remote Sync propagates the confirmed local changes normally.

## Optional AI-assisted workflow

ChatGPT, Codex, Claude, and similar tools can research a BOM and produce the
same standard package file. AI is not required, integrated, or contacted by
Inventorinator.

### Prompt template

> Research the complete official BOM for [KIT NAME AND VARIANT]. Use primary
> manufacturer documentation whenever possible. Create one valid
> `.inventorinator-kit.json` package using Inventorinator schema version 1.
> Include stable IDs, sections, every BOM part and quantity, item type,
> material/brand when known, associated machines, and HTTP(S) source records.
> Do not guess missing values. Use `other` when no supported item type fits.
> Return only the JSON file content.

Always review the cited sources and Inventorinator's preview before importing.
AI-generated BOMs can be incomplete or wrong.

## Package format

Required root fields:

- `format`: exactly `inventorinator-kit`
- `schemaVersion`: `1`
- `id`: stable package ID using letters, numbers, `.`, `_`, or `-`
- `name`: kit name
- `sections`: one or more section objects
- `parts`: one or more BOM part objects

Optional root fields:

- `description`
- `sources`: source objects with `url` and optional `title`
- `machines`: associated machine objects

Each section requires `id` and `name`; `description` is optional.

Each part requires:

- `id`: stable ID unique within the package
- `name`
- `type`: one of `other`, `fastener`, `filament`, `printedPart`, `resin`,
  `nozzle`, `heatBreak`, `heatBlock`, or `sock`
- `section`: the ID of a declared section
- `quantity`: number greater than zero

Optional part fields are `material`, `brand`, `unitCost`, `compatibility`, and
`sources`.

Each machine requires `id`, `name`, and `type`. Optional machine fields are
`model`, `address`, and `sources`.

All source URLs must use HTTP or HTTPS. Files larger than 10 MB are rejected.
See
[`examples/example.inventorinator-kit.json`](../examples/example.inventorinator-kit.json)
for a complete package.

## Safety and privacy

- Import happens only after local validation and explicit confirmation.
- The preview shows every section, part, quantity, machine, and source count.
- New parts begin at zero stock.
- Inventorinator does not execute instructions contained in a package.
- Import does not require or contact an AI provider.
- Remote Sync runs only if the user has already configured it.
